# Трекер задач: локальный Markdown

Задачи и спеки для этого репозитория хранятся как markdown-файлы в `.scratch/`.

## Соглашения

- Одна фича — одна директория: `.scratch/<feature-slug>/`
- Спек — это `.scratch/<feature-slug>/spec.md`
- Задачи на реализацию — по одному файлу на тикет: `.scratch/<feature-slug>/issues/<NN>-<slug>.md`, нумерация с `01`; единый файл со всеми тикетами не использовать
- Состояние триажа записывается строкой `Status:` в начале каждого файла задачи (строки ролей — в `triage-labels.md`)
- Комментарии и история обсуждения дописываются в конец файла под заголовком `## Comments`

## Когда скилл говорит "publish to the issue tracker"

Создать новый файл в `.scratch/<feature-slug>/` (при необходимости создав директорию).

## Когда скилл говорит "fetch the relevant ticket"

Прочитать файл по переданному пути. Обычно пользователь передаёт путь или номер задачи напрямую.

## Операции wayfinding

Используются `/wayfinder`. **Карта** — файл с одним **дочерним** файлом на тикет.

- **Map**: `.scratch/<effort>/map.md` (тело Notes / Decisions-so-far / Fog).
- **Child ticket**: `.scratch/<effort>/issues/NN-<slug>.md`, нумерация с `01`, вопрос в теле файла. Строка `Type:` фиксирует тип тикета (`research`/`prototype`/`grilling`/`task`); строка `Status:` фиксирует `claimed`/`resolved`.
- **Blocking**: строка `Blocked by: NN, NN` в начале файла. Тикет разблокирован, когда все перечисленные в ней файлы имеют `Status: resolved`.
- **Frontier**: сканировать `.scratch/<effort>/issues/` на открытые, разблокированные и никем не занятые тикеты; первым по номеру.
- **Claim**: установить `Status: claimed` и сохранить до начала работы.
- **Resolve**: дописать ответ под заголовком `## Answer`, установить `Status: resolved`, затем дописать контекстный указатель (gist + ссылка) в Decisions-so-far карты в `map.md`.
