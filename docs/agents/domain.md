# Доменные документы

Как инженерные скиллы должны использовать доменную документацию этого репозитория при изучении кодовой базы.

## Перед изучением прочитайте

- **`GLOSSARY.md`** в корне репозитория, или
- **`GLOSSARY-MAP.md`** в корне, если он существует: он указывает на один `GLOSSARY.md` на контекст. Читайте каждый, относящийся к теме.
- **`docs/adr/`**: читайте ADR, затрагивающие область, над которой вы собираетесь работать. В мультиконтекстных репозиториях также проверяйте `src/<context>/docs/adr/` на предмет решений, ограниченных контекстом.

Если каких-то из этих файлов не существует, **молча продолжайте**. Не акцентируйте внимание на их отсутствии; не предлагайте создать их заранее. Скилл `/domain-modeling` (достижимый через `/grill-with-docs` и `/improve-codebase-architecture`) создаёт их лениво, когда термины или решения реально сформированы.

## Структура файлов

Репозиторий с одним контекстом (большинство репозиториев):

```
/
├── GLOSSARY.md
├── docs/adr/
│   ├── 0001-event-sourced-orders.md
│   └── 0002-postgres-for-write-model.md
└── src/
```

Мультиконтекстный репозиторий (наличие `GLOSSARY-MAP.md` в корне):

```
/
├── GLOSSARY-MAP.md
├── docs/adr/                          ← решения на уровне всей системы
└── src/
    ├── ordering/
    │   ├── GLOSSARY.md
    │   └── docs/adr/                  ← решения, специфичные для контекста
    └── billing/
        ├── GLOSSARY.md
        └── docs/adr/
```

## Используйте словарный запас глоссария

Когда ваш результат называет доменную концепцию (в заголовке задачи, предложении о рефакторинге, гипотезе, имени теста), используйте термин как он определён в `GLOSSARY.md`. Не скатывайтесь к синонимам, которых глоссарий избегает.

Если нужной концепции в глоссарии ещё нет — это сигнал: либо вы изобретаете язык, которым проект не пользуется (переосмыслите), либо есть реальный пробел (зафиксируйте его для `/domain-modeling`).

## Отмечайте конфликты с ADR

Если ваш результат противоречит существующему ADR, явно укажите на это, а не перекрывайте его молча:

> _Противоречит ADR-0007 (event-sourced orders), но стоит переоткрыть, потому что…_
