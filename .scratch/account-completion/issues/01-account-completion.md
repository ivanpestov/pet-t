# 01: Реализовать автодополнение accounts через ledger accounts

**What to build:** Скрытый режим `t --complete <текущее> <предыдущее>`,
выводящий кандидатов дополнения для первого позиционного аргумента из
вывода `ledger accounts`, с префиксной фильтрацией в бинарнике.
Поведение Таймера, коды выхода, вывод и записи Ledger не меняются.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [ ] Режим `t --complete <текущее> <предыдущее>` распознаётся на
      границе CLI до обычного разбора аргументов; строка usage и код 2
      для обычных ошибок разбора не меняются.
- [ ] Для предыдущего слова `t`: кандидаты — вывод `ledger accounts`
      (наследуется окружение, LEDGER_FILE читает сама команда),
      переданный без изменений и отфильтрованный по префиксу
      `<текущее>` (байтовое, регистрозависимое сравнение); пустое
      текущее слово — весь список.
- [ ] Для любого другого предыдущего слова вывод пуст.
- [ ] Путь дополнения не инициализирует Ctrl+C handler, монитор сна,
      уведомления и сценарий Таймера; завершается сразу после печати.
- [ ] При любом сбое (ledger не найден, LEDGER_FILE отсутствует или
      недоступен, битый файл) — пустой stdout, код 0, пустой stderr;
      stderr дочернего процесса подавляется.
- [ ] Новых зависимостей крейта нет; новый код под действием
      `#![forbid(unsafe_code)]`.
- [ ] Вся логика дополнения расположена в адаптерах; домен,
      application и сценарий Таймера не затронуты.
- [ ] Процессные тесты: подмена `ledger` через PATH покрывает полный
      список, префиксный фильтр, регистрозависимость, пустой вывод
      для второго аргумента, отсутствие ledger и LEDGER_FILE.
- [ ] Существующие integration-тесты не редактировались и проходят;
      форматирование, сборка, clippy с запретом предупреждений и
      полный набор тестов проходят.
- [ ] Ручные шаги установки (symlink `~/.local/bin/t`, замена строки
      `complete -F _todo t` на `complete -C` в
      `~/.bash.d/bash_aliases`) задокументированы в спеке и не
      автоматизируются.
