# Автодополнение accounts из Ledger

## Problem Statement

Пользователь вызывает Таймер с аргументом account, но имена accounts
приходится помнить наизусть или искать в Ledger. Ошибка в имени
заметна только после разбора аргументов: Таймер завершается с кодом 2,
не начав работу. Хочется дополнять существующие accounts клавишей TAB
в shell.

## Solution

Бинарник обзаводится скрытым служебным режимом `t --complete <текущее>
<предыдущее>`: он выводит кандидатов дополнения построчно и
завершается. Регистрация в bash — через `complete -C`, привязанный к
команде `t`. Источником кандидатов служит внешняя команда
`ledger accounts`: она читает LEDGER_FILE из окружения, разбирает
timeclock-формат (`i`/`o`) и выдаёт уникальные отсортированные
accounts. Вывод пробрасывается без фильтрации, после чего бинарник
отбирает строки с префиксом, равным текущему слову.

Наблюдаемое поведение Таймера не меняется: режим `--complete`
обособлен от обычного разбора аргументов и не затрагивает сценарий
прогона, коды выхода, вывод и записи Ledger.

## User Stories

1. Как пользователь, я хочу нажать TAB после `t`, чтобы увидеть все
   accounts из текущего LEDGER_FILE, и выбрать нужный без запоминания.
2. Как пользователь, я хочу набрать префикс (`t wo<TAB>`) и увидеть
   только полные accounts, начинающиеся с него, чтобы сузить список.
3. Как пользователь, я хочу, чтобы дополнение уважало переменную
   LEDGER_FILE текущей сессии, в том числе переключённую
   `change_ledger_file`, чтобы всегда предлагать актуальные accounts.
4. Как мейнтейнер, я хочу, чтобы путь дополнения не инициализировал
   Ctrl+C, D-Bus и уведомления, чтобы TAB отзывался мгновенно и не
   имел побочных эффектов.
5. Как мейнтейнер, я не хочу зависимостей крейта: `ledger` — внешняя
   runtime-команда, установленная в системе, а не библиотека.

## Implementation Decisions

- Протокол: `t --complete <текущее-слово> <предыдущее-слово>`;
  кандидаты — по строке на stdout; всегда код выхода 0; stderr всегда
  пустой. Флаг скрытый: строка usage не меняется, флаг нигде не
  афишируется.
- Дополнение предлагает accounts только для первого позиционного
  аргумента (предыдущее слово — `t`). Второй аргумент (минуты), опции
  и иные позиции не дополняются: пустой вывод.
- Кандидаты — вывод `ledger accounts` как есть, без фильтрации через
  доменную валидацию: ledger может выдать и то, что Таймер отклонил
  бы (например, account с пробелом) — это осознанное решение
  источнику данных.
- Бинарник отбирает кандидатов по префиксу: байтовое сравнение,
  регистрозависимое (accounts регистрозависимы по правилам домена).
  Пустое текущее слово — все accounts. Фильтрация выполняется в
  бинарнике, а не отдаётся readline: поведение закреплено протоколом.
- Слои: весь путь дополнения живёт в адаптерах (обнаружение флага при
  разборе аргументов, вызов `ledger`, фильтрация, печать). Домен и
  application не участвуют, новые порты не вводятся, сценарий Таймера
  и его тесты не затрагиваются.
- Сбои любого рода (команда `ledger` не найдена, LEDGER_FILE
  отсутствует или недоступен, битый файл) приводят к пустому stdout,
  коду 0; stderr дочернего процесса подавляется полностью (ledger
  пишет диагностику даже при коде 0). Собственной диагностики режим
  не выводит.
- Без кэша: обращение к `ledger accounts` на каждое нажатие TAB
  (~4 мс на файлах реального размера).
- Установка на машине пользователя (вне репозитория): symlink
  `~/.local/bin/t` → `~/projects/pet/t/target/debug/t`; в
  `~/.bash.d/bash_aliases` удаляется мёртвая строка
  `complete -F _todo t` и добавляется регистрация `complete -C`.
  Todo-семантика утилите не присваивается.
- Новых зависимостей крейта нет; запрет `unsafe` распространяется на
  новый код автоматически (крейтовый атрибут).

## Testing Decisions

- Поведение дополнения проверяется на процессном шве: запуск
  собранного бинарника `t --complete ...` с подменой `ledger` через
  PATH (заглушка печатает заданный список), как это делают
  существующие integration-тесты для `date` и `notify-send`.
- Проверяются: полный список при пустом префиксе, фильтрация по
  префиксу (`wo` → только подходящие полные accounts), регистровая
  чувствительность, пустой вывод для второго аргумента, подавление
  stderr и код 0 при отсутствии команды `ledger` (PATH без неё) и при
  отсутствующем LEDGER_FILE.
- Unit-тесты не добавляются: логики домена в дополнении нет, тестировать
  нечего; тонкие хелперы фильтрации, если появятся, покрываются
  процессными тестами через протокол.
- Существующие integration-тесты не редактируются и проходят.

## Out of Scope

- Поддержка zsh и fish (в системе только bash).
- Кэширование списка accounts.
- Дополнение промежуточных сегментов (`work` для `work:project`).
- Дополнение минут и опций командной строки.
- Фильтрация кандидатов через доменную валидацию Account.
- Изменение сценария прогона Таймера, портов, доменных типов.
- Автоматизация установки symlink и регистрации в bash (ручной шаг).

## Further Notes

- Утилита не имеет отношения к todo; строка `complete -F _todo t`
  в `~/.bash.d/bash_aliases` — чужеродный пережиток и подлежит
  удалению при установке.
- `ledger` (3.3.2) читает LEDGER_FILE из окружения сам; повторный
  экспорт не нужен.
- Glossary и ADR не затрагиваются: новых доменных терминов нет,
  решение обратимо и фиксируется спекой.
