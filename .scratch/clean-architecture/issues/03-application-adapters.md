# 03: Ввести application и adapters, сделать main композицией

**What to build:** Отделить сценарий прогона Таймера от инфраструктуры: цикл
событий, исход работы и порты к часам, хранилищу Ledger и уведомлениям живут в
application, конкретные реализации — в adapters, а бинарник только собирает их и
переводит исход в код выхода. Поведение, тексты и байты вывода прежние.

**Blocked by:** 02 — Выделить библиотечный крейт и чистый домен.

**Status:** ready-for-agent

- [ ] Порты `Clock`, `LedgerWriter` и `Notifier` описаны в application и
      передаются как трейт-объекты; состояние и диагностика передаются как
      отдельные `&mut dyn Write` без новых трейтов вывода.
- [ ] `Config`, `Event`, `Outcome` и цикл Таймера живут в application; сценарий
      владеет циклом и жизненным циклом Учитываемого периода, а не бинарник.
- [ ] `Config` содержит `Option<Account>`; `Outcome` хранит только сведения,
      влияющие на код выхода. Коды 0, 1, 2 и 130 вычисляются только на
      границе CLI и соответствуют матрице завершения из спецификации.
- [ ] Разбор аргументов, проверка положительного целого числа минут и
      переполнений выполняются в адаптере CLI; справка по использованию и код 2
      остаются на границе.
- [ ] Открытие файла Ledger, проверка `LEDGER_FILE` и добавление недостающего
      перевода строки остаются в адаптере; обнаружение незакрытого периода
      делегируется доменному правилу без дублирования.
- [ ] Часы реализуются системной командой с прежними аргументами, уведомления
      — прежней командой с fallback на звонок и сообщение в переданный поток
      диагностики, а Ctrl+C — отдельным адаптером `interrupt`.
- [ ] Рукопожатие при подготовке ко сну сохранено: период закрывается до
      подтверждения, inhibitor освобождается после него, собственного таймаута
      нет.
- [ ] Ошибки типизированы по слоям, отображаются прежними текстами и выводятся
      один раз; коды выхода, stdout, stderr и байты Ledger не изменились.
- [ ] In-process тесты application используют фейки портов и синтетические
      события без новых зависимостей и абстракции монотонного времени.
- [ ] Тесты покрывают открытие периода, естественное завершение через
      `Duration::ZERO`, ошибку закрытия с уведомлением, прерывание,
      подтверждение сна после попытки закрытия, отказ мониторинга, разрыв
      канала и ошибки отображения.
- [ ] Конкретные адаптеры in-process не тестируются; fallback уведомления
      остаётся покрытым процессными тестами.
- [ ] Новые зависимости не добавлены.
- [ ] Существующие integration-тесты не редактировались и проходят;
      форматирование, сборка, clippy с запретом предупреждений и полный набор
      тестов проходят.
