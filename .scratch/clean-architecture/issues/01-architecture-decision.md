# 01: Зафиксировать архитектурное решение и термин Ledger

**What to build:** Принять и записать решение о слоистой структуре приложения
и о правиле зависимостей между слоями, чтобы будущие изменения опирались на
зафиксированный контракт, а не на устные договорённости. Одновременно закрыть
пробел в доменном словаре: термин Ledger используется, но не определён.

**Blocked by:** None (can start immediately).

**Status:** resolved

- [x] ADR в каталоге решений описывает контекст, решение, последствия и
      рассмотренные альтернативы.
- [x] ADR фиксирует: библиотечный крейт и тонкий бинарник с прежним именем,
      три слоя и направление зависимостей, порты только на IO-границах,
      запрет новых зависимостей, отсутствие `mod.rs`.
- [x] ADR фиксирует три seam: процессный, чистого домена и application.
      Для двух библиотечных seam отменяется решение предыдущих specs
      «единственный seam — процесс», и объясняется причина.
- [x] В доменный глоссарий добавлен Ledger как журнал записей о начале и
      конце Учитываемых периодов, без деталей формата, хранения и без
      смешения с Учитываемым периодом.
- [x] Исторические specs в `.scratch` не изменены.
- [x] Изменения затрагивают только документацию; код и зависимости не тронуты.
