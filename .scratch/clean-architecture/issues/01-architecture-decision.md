# 01: Зафиксировать архитектурное решение и термин Ledger

**What to build:** Принять и записать решение о слоистой структуре приложения
и о правиле зависимостей между слоями, чтобы будущие изменения опирались на
зафиксированный контракт, а не на устные договорённости. Одновременно закрыть
пробел в доменном словаре: термин Ledger используется, но не определён.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [ ] ADR в каталоге решений описывает контекст, решение, последствия и
      рассмотренные альтернативы.
- [ ] ADR фиксирует: библиотечный крейт и тонкий бинарник с прежним именем,
      три слоя и направление зависимостей, порты только на IO-границах,
      запрет новых зависимостей, отсутствие `mod.rs`.
- [ ] ADR фиксирует, что для чистого домена отменяется решение предыдущих
      specs «единственный seam — процесс», и объясняет причину.
- [ ] В доменный глоссарий добавлен Ledger как файл с записями Учитываемых
      периодов, без деталей формата и без смешения с Учитываемым периодом.
- [ ] Исторические specs в `.scratch` не изменены.
- [ ] Изменения затрагивают только документацию; код и зависимости не тронуты.
